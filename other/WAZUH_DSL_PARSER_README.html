Wazuh DSL Parser

Overview

A comprehensive DSL parser for converting Wazuh XML rules to a structured DSL format. This parser supports all operators from the Wazuh rule syntax except srcgeoip and dstgeoip (to be added later).

Features

✅ Core Matchers (Filtering Events)

  • contains("text") - Simple substring match
  • regex(r"\d+") - Regex match
  • pcre(r"(?<=a)b") - PCRE regex with lookarounds
  • field["name"] == "val" - Dynamic field access
  • src_ip in 10.0.0.0/8 - IP/CIDR matching
  • dst_ip in 192.168.1.1 - Destination IP matching
  • src_port == 443 - Source port matching
  • dst_port == 80 - Destination port matching
  • protocol == "tcp" - Protocol matching
  • user == "admin" - User matching (expands to src_user OR dst_user)
  • url contains "/login" - URL matching
  • event_id == 4625 - Event ID matching
  • status == "failed" - Status matching
  • agent.name == "web01" - Hostname matching
  • program == "sshd" - Program name matching
  • system.name == "x" - System name matching
  • action == "drop" - Action matching
  • data contains "error" - Data field matching
  • extra_data == "x" - Extra data matching
  • time between(18:00, 07:00) - Time range matching
  • day in [mon..fri] - Weekday matching
  • decoder.name == "json" - Decoder matching
  • category == "firewall" - Category matching
  • not ... - Negation

✅ Logic & Dependencies (Rule Chain)

  • if_sid = ["100", "200"] - Parent rule IDs
  • if_group = ["auth", "ssh"] - Parent rule groups
  • if_level >= 5 - Parent rule level
  • if_matched_sid = ["100"] - Aggregation rule tracking
  • if_matched_group = ["ssh"] - Aggregation group tracking
  • caused_by(sid: 100) - Rule dependency expression
  • caused_by(group: "auth") - Group dependency
  • caused_by(level >= 10) - Level dependency

✅ Aggregation & State (Temporal State Store)

  • frequency = 5 - Event count threshold
  • timeframe = 60 - Time window in seconds
  • group_by = [src_ip, user] - Group aggregation keys
  • unique_count(src_ip) > 10 - Unique value tracking
  • global_frequency = 100 - Cross-agent aggregation

Supported group_by fields:

  • src_ip, dst_ip, src_port, dst_port
  • protocol, action, event_id, url
  • user, src_user, data, extra_data
  • status, system_name, location
  • field["custom_field"] - Dynamic field

✅ Database & List Operators

  • src_ip in @list_name - Check if value exists in list
  • val not in @list_name - Key must not exist
  • ip in @cidr_list - IP against CIDR list (RadixTree)

✅ Rule Options & Actions

  • no_log = true - Don't write to alerts.json
  • no_full_log = true - Strip raw log payload
  • alert_by_email = true - Force email alert
  • no_email_alert = true - Prevent email alert
  • log_alert = true - Force log (bypass min level)
  • ignore = 300 - Cooldown in seconds after firing
  • overwrite = true - Replace existing rule with same ID
  • groups = ["auth", "ssh"] - Rule grouping tags
  • mitre = ["T1078", "T1110"] - MITRE ATT&CK mapping
  • info = "..." - Arbitrary metadata
  • description = "..." - Human readable text

❌ Not Implemented (Will Add Later)

  • src_geo.country == "US" - Source GeoIP
  • dst_geo.city == "Paris" - Destination GeoIP

Architecture

The parser consists of three main components:

1. Lexer (Tokenizer)

Converts raw DSL text into tokens:

let mut lexer = Lexer::new(dsl_text);
let token = lexer.next_token()?;

Supported tokens:

  • Keywords: rule, level, when, frequency, group_by, etc.
  • Operators: ==, !=, >, <, >=, <=, in, not, and, or
  • Literals: strings, integers, floats, booleans, raw strings (r"...")
  • Punctuation: (), [], {}, ,, ., :, ;, @

2. Parser (AST Builder)

Builds an Abstract Syntax Tree from tokens:

let mut parser = Parser::new(dsl_text)?;
let rule = parser.parse_rule()?;

The parser uses recursive descent parsing with operator precedence:

  • Expression parsing: OR > AND > NOT > Primary
  • Supports parenthesized expressions
  • Type-aware field parsing (ports as u16, IPs as strings, etc.)

3. AST Nodes

Structured representation of rules:

pub struct WazuhRule {
    pub id: String,
    pub level: u32,
    pub name: String,
    pub description: Option<String>,
    pub if_sid: Option<Vec<String>>,
    pub condition: Option<Expression>,
    pub frequency: Option<FrequencyClause>,
    pub group_by: Option<GroupByClause>,
    // ... more fields
}

pub enum Expression {
    And(Box<Expression>, Box<Expression>),
    Or(Box<Expression>, Box<Expression>),
    Not(Box<Expression>),
    Contains(FieldRef, String),
    Regex(FieldRef, String),
    SrcIpIn(IpValue),
    SrcPortEq(u16),
    // ... 50+ expression types
}

Usage Examples

Example 1: Simple Field Matching

rule 100
level = 5
name = "FortiGate Base Rule"
when
  field["vendor"] == "fortinet"
end

Example 2: Rule with Parent Dependencies

rule 111501
level = 1
name = "FortiGate Messages Grouped"
if_sid = ["111500", "111618"]
end

Example 3: Complex Conditions

rule 111502
level = 5
name = "Failed Login Attempt"
if_sid = ["111501"]
when
  event_id == 4625 and status == "failed" and not user == "admin"
groups = ["authentication", "failed_login"]
mitre = ["T1078", "T1110"]
end

Example 4: Aggregation Rule

rule 200
level = 10
name = "Multiple Failed Logins"
frequency = 5
timeframe = 300
group_by = [src_ip, user]
when
  status == "failed"
end

Example 5: Time-based Rule

rule 300
level = 7
name = "Off-hours Access"
when
  time between(18:00, 07:00) and day in [mon..fri]
end

Example 6: List-based Rule

rule 400
level = 8
name = "Blocked User Login"
when
  user in @blocked_users and status == "success"
end

XML to DSL Conversion

The parser includes utilities for converting Wazuh XML tags to DSL expressions:

use std::collections::HashMap;
use security_rule_engine::wazuh_dsl_parser::*;

let mut attrs = HashMap::new();
attrs.insert("name".to_string(), "vendor".to_string());

let expr = xml_tag_to_dsl_expression("field", "fortinet", &attrs)?;
// Returns: Expression::FieldEq(field["vendor"], "fortinet")

XML Tag Mappings

XML Tag DSL Equivalent Example
<match>text</match> message.contains("text") Substring match
<regex>pattern</regex> message.regex(r"pattern") Regex match
<field name="x" type="pcre2">p</field> field["x"].pcre(r"p") PCRE field match
<srcip>10.0.0.0/8</srcip> src_ip in 10.0.0.0/8 IP/CIDR match
<srcport>443</srcport> src_port == 443 Port match
<protocol>tcp</protocol> protocol == "tcp" Protocol match
<user>admin</user> user == "admin" User match
<id>4625</id> event_id == 4625 Event ID match
<decoded_as>json</decoded_as> decoder.name == "json" Decoder match
<list lookup="match_key">@list</list> value in @list List lookup

DSL Serialization

Convert AST back to DSL format:

let rule = WazuhRule { /* ... */ };
let dsl_string = rule_to_dsl(&rule);
println!("{}", dsl_string);

Output:

rule 100
level = 5
name = "Test Rule"
when
  field["vendor"] == "fortinet"
end

Implementation Notes

Type Inference

  • Ports are parsed as u16 for efficient comparison
  • Event IDs are parsed as u64
  • IPs are stored as strings but can be validated
  • CIDR blocks are distinguished from IPs by presence of /

Performance Optimizations

  • Pre-compile regex patterns at startup (not per-event)
  • Use memchr for substring matching (Boyer-Moore)
  • CIDR lookups use RadixTree for O(1) average case
  • Weekdays use bitmask (u8) for single-cycle comparison

State Management

  • Frequency counters require Redis/Memcached for TTL
  • State keys: RuleID + GroupByFields
  • Unique counts use Set<T> storage
  • Global frequency requires shared central DB

Security Considerations

  • same_data and same_extra_data can cause high memory usage
  • different_url tracking can be memory-intensive
  • List lookups should validate file existence at parse time
  • Consider rate limiting for aggregation rules

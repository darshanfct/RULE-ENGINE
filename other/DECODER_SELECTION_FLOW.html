Summary: How Decoder Selection Works

The system uses a sequential detection pattern where each decoder tests the incoming log until a match is found. It's a first-match-wins approach.

Number of Functions Involved: 7 main functions

Purpose: Entry point for all log processing

pub fn process(&self, line: &str) -> NormalizedEvent {
    let mut evt = if let Some(evt) = self.svc.decode(line) {
        evt
    } else {
        // Fallback: empty normalized event
        NormalizedEvent {
            timestamp: Utc::now(),
            raw_message: line.to_string(),
            ..Default::default()
        }
    };
    
    // Add event identity
    crate::normalized_events::assign_event_identity(&mut evt);
    evt
}

What It Does:

  • Calls decoder service
  • If no decoder matches, returns fallback (empty event)
  • Always returns something (never fails)

Function 3: DecoderRegistry::decode_line()

Location: src/decoder.rs:2538

Purpose: Orchestrates detect → parse → normalize

Code:

pub fn decode_line(&self, line: &str) -> Option<NormalizedEvent> {
    if let Some(dec) = self.detect_decoder(line) {  // Find decoder
        if let Some(raw) = dec.parse(line) {         // Parse log
            return Some(dec.normalize(raw));         // Normalize fields
        }
    }
    None
}

What It Does:

  1. Detects which decoder to use
  2. Parses log with that decoder
  3. Normalizes to standard format
  4. Returns None if any step fails

Function 4: DecoderRegistry::detect_decoder() ⭐

Location: src/decoder.rs:2528

Purpose: THE KEY FUNCTION - Selects which decoder to use

Code:

pub fn detect_decoder(&self, line: &str) -> Option<Arc<dyn Decoder>> {
    let snapshot = self.decoders.load();  // Get current decoder list
    
    for dec in snapshot.iter() {
        if dec.detect(line) {             // Test this decoder
            return Some(Arc::clone(dec)); // ✅ FOUND! Return it
        }
    }
    
    None  // ❌ No decoder matched
}

Algorithm:

  • Sequential search through all loaded decoders
  • First-match-wins - stops at first decoder that matches
  • Order matters! Decoders tested in load order

Critical Points:

  • Uses ArcSwap for lock-free hot-reload
  • Returns Arc<dyn Decoder> (trait object)
  • Order of decoders affects which one is chosen

Function 6: JsonConfiguredDecoder::detect_impl() ⭐

Location: src/decoder.rs:1997

Purpose: THE DETECTION LOGIC - Tests if log matches this decoder

Code:

fn detect_impl(&self, line: &str) -> bool {
    if let Some(d) = &self.config.detect {
        
        // 1. Contains check
        if let Some(contains) = &d.contains {
            for c in contains.iter() {
                if line.contains(c) {
                    return true;  // ✅ MATCH
                }
            }
        }
        
        // 2. StartsWith check
        if let Some(starts) = &d.startswith {
            for s in starts.iter() {
                if line.starts_with(s) {
                    return true;  // ✅ MATCH
                }
            }
        }
        
        // 3. JSON key exists
        if let Some(keys) = &d.json_key_exists {
            if let Ok(v) = serde_json::from_str::<JsonValue>(line) {
                for k in keys.iter() {
                    if v.get(k).is_some() {
                        return true;  // ✅ MATCH
                    }
                }
            }
        }
        
        // 4. Regex match
        if let Some(r) = &self.detect_regex {
            if r.is_match(line) {
                return true;  // ✅ MATCH
            }
        }
    }
    
    false  // ❌ NO MATCH
}

Detection Methods:

Method Example Config Matches
contains ["sophos", "firewall"] Any log containing "sophos" OR "firewall"
startswith ["<134>"] Any log starting with "<134>"
json_key_exists ["event_type"] Any JSON log with "event_type" field
regex "(?i)sophos.*xg" Any log matching regex pattern

Logic: ANY match → TRUE (OR condition)

🎯 Key Insights

1. First-Match-Wins

  • Decoders tested sequentially
  • First matching decoder is used
  • Order matters! More specific decoders should be first

2. Multiple Detection Methods

  • contains - Simple substring match (fastest)
  • startswith - Prefix match
  • json_key_exists - Structured JSON detection
  • regex - Complex pattern matching (slowest)

3. OR Logic

  • ANY detection method matching → decoder selected
  • Within contains, ANY string matching → decoder selected

4. Performance

  • Fast path: contains check (substring search)
  • Slow path: Regex matching
  • Order optimization: Put common logs first

5. Hot-Reload

  • Uses ArcSwap for lock-free updates
  • File watcher monitors ./decoders/vendors/
  • No restart needed for new decoders

6. Fallback Behavior

  • If NO decoder matches → returns empty NormalizedEvent
  • System NEVER fails, always produces output
  • vendor field empty indicates no decoder matched

📊 Performance Characteristics

Aspect Details
Time Complexity O(n × m) where n=number of decoders, m=detection checks
Typical Case 1-3 decoders tested (early match)
Worst Case All decoders tested (no match)
Optimization Stop at first match (short-circuit)
Concurrency Lock-free read via ArcSwap

🎓 Summary

7 Functions work together:

  1. DecoderEngine::process() - Entry point
  2. DecoderService::decode() - Service layer
  3. DecoderRegistry::decode_line() - Orchestration
  4. DecoderRegistry::detect_decoder() - Selects decoder ⭐
  5. JsonConfiguredDecoder::detect() - Trait impl
  6. JsonConfiguredDecoder::detect_impl() - Detection logic ⭐
  7. DecoderRegistry::load_decoders() - Loads from disk

Key Decision Points:

  • Sequential search (first-match-wins)
  • 4 detection methods (contains, startswith, json_key, regex)
  • OR logic (any match succeeds)
  • Fallback (returns empty event if no match)

The magic happens in detect_decoder() + detect_impl()!
